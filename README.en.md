A [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) (DSH) plugin. After every turn ends, it reads the whole conversation with the model you specify (local Ollama / LM Studio, or that Qwen box on your LAN), compresses it into one title of a fixed length, and writes it back to the session.

## What it solves

DSH ships two automatic title schemes. Both get the timing and the model wrong:

- Built-in: one title after the first message, generated by the main model you are using.
- The plugin marketplace's "updates as the chat goes (experimental)": re-calls the main model to rewrite the title on every new prompt.

Both hand the title to the main model, and both change it too early or too often. This plugin takes a different approach:

- You want a title after **every turn ends**, written by **the model you choose**, summarizing the whole conversation into a fixed length. Install it.
- You want a local / LAN small model to do this job, saving main-model tokens, and you do not want it touching every message. Install it.
- You only want the built-in one-shot title after the first message and are fine with whatever the main model gives. No need to install.
- You do not want titles changed automatically at all and want to do it all by hand. Do not install.

## How it works

```
turn/end ──▶ collect all human messages in this session ──▶ pick "first + recent window" under a byte budget
                                                                     │
                                                                     ▼
                                                    configured model (thinking off) + 256 tokens
                                                                     │
                                                                     ▼
                                               truncate by character count (default 20) ──▶ sessionTitle.rename()
```

- Titles are still written as log events by DSH's built-in `session-title` service, so they persist through listing, replay, and resume, the same as official title behavior.
- `cordis.patch.yml` disables the shipped `first-prompt` provider. If you also have the experimental `all-prompts` bundle installed, disable that too — the service accepts only one provider.
- The plugin listens to `turn/end` on `session/event`: after every turn ends it takes **all human user messages** in that session (`source.kind === 'user'`), selects them within a byte budget by "first anchor + most recent window", and hands them to the configured model to summarize.
- The title call **requests thinking off** (when the route supports an `off` mode), so the 256-token budget is not eaten by reasoning.
- Subagent sessions are skipped by default; only top-level sessions get a title. If the previous round of the same session is still generating, a new round cancels it and the latest conversation wins.

## Quick start

```sh
# 1. Clone into ~/.dsh/plugins/dsh-session-title-on-turnend
git clone https://github.com/gpboyer2/dsh-session-title-on-turnend.git ~/.dsh/plugins/dsh-session-title-on-turnend

# 2. Register it with a profile (a CLI-managed profile, e.g. web / main)
dsh plugin --profile <your-profile> add link:$HOME/.dsh/plugins/dsh-session-title-on-turnend

# 3. Restart DSH
```

> The `desktop` profile is owned exclusively by DeepSeek Harness.app; the CLI `dsh plugin --profile desktop …` is rejected. On the desktop app, install from the in-app "Plugins" page, or edit the profile's `dependencies` and symlink it, then restart.

The bundled `cordis.patch.yml` does two things automatically: disables the shipped `first-prompt` title provider and inserts this plugin. No need to edit the profile's patch file by hand.

**Verify**: after restart, open any session and ask one question. Wait a few seconds after the answer ends, then check whether the sidebar title was replaced with a summary; also check whether `~/.dsh/logs/session-title-on-turnend.log` has a new line.

## Features

| Capability | Description |
| --- | --- |
| **Only at turn end** | Fires once after every `turn/end`, never mid-conversation. |
| **Model is selectable** | `provider` + `model` point at any DSH route; default is the LAN `local-31-99/qwen3.8-27b`. |
| **Length is bounded** | `maxChars` truncates by Unicode code point (a Han character counts as 1), default 20; emoji are never cut in half. |
| **Input has a budget** | `maxInputBytes` caps the payload sent to the model; over budget it selects by "first + recent window", so it does not grow without bound as the conversation grows. |
| **Thinking off** | When the route supports an `off` mode, it requests reasoning off and leaves the 256-token output budget to the title itself. |
| **Failures do not corrupt** | Model not started, route missing, timeout: one log line only; the old title stays. |
| **Skips subagents** | Only top-level sessions get titles by default; subagent sessions are left alone. |
| **Preempts stale requests** | A new round in the same session cancels the unfinished title generation from the previous round. |

## Configuration

Defaults (`DEFAULTS` in `lib/index.js`):

| Option | Default | Description |
| --- | --- | --- |
| `enabled` | `true` | Master switch. |
| `provider` | `magpie` | Route for the title model. |
| `model` | `local-31-99/qwen3.8-27b` | Title model; default is Qwen3.8 27B on LAN 31.99. |
| `maxChars` | `20` | Maximum title characters (by Unicode code point, a Han character counts as 1). |
| `maxInputBytes` | `16384` | Byte cap on the message payload sent to the model. |
| `maxOutputTokens` | `256` | Output token cap; guards against thinking / runaway output. |
| `timeoutMs` | `60000` | End-to-end timeout for one generation. |
| `skipSubagents` | `true` | Skip subagent sessions. |
| `debug` | `true` | Write one diagnostic line to the log. |
| `logFile` | `~/.dsh/logs/session-title-on-turnend.log` | Log location. |
| `systemPrompt` | `null` | Custom system prompt; `null` uses the built-in Chinese prompt. |

To change them, override the plugin entry in the profile's `cordis.patch.yml`:

```yaml
- id: session-title-on-turnend
  name: dsh-session-title-on-turnend
  config:
    provider: magpie
    model: local-31-99/qwen3.8-27b
    maxChars: 20
```

**The length-cap gotcha**: the `session-title` service itself has a hard `maxTitleBytes` cap (80 bytes out of the box). 20 Han characters is 60 bytes, safe; for 30 Han characters you must also widen `maxTitleBytes` on that service line (about 90 bytes), otherwise the service truncates it again on write.

## Logging and diagnostics

`~/.dsh/logs/session-title-on-turnend.log` gets one line per turn: trigger, how many messages were selected, model response, lengths before and after truncation, and the reason on failure.

If the title did not change, check first:

| Symptom | Check first |
| --- | --- |
| No new log line | Plugin not loaded: does the profile's `dsh.profile.bundles` contain it, and did the restart complete. |
| Log says "skip subagent" | This is a subagent session; skipped by design. |
| Log has a model error | Local model not running, route name wrong, timeout; the old title is kept. |
| Title came out shorter | Hit the service's 80-byte hard cap; widen `maxTitleBytes` or lower `maxChars`. |

## Architecture

```
lib/index.js           all plugin logic: turn/end listener, message filtering, budget selection, model call, truncation, rename
cordis.patch.yml       bundle patch: disable the shipped first-prompt provider, insert this plugin
test/                  17 pure-logic and full-chain smoke tests
```

Design constraint: titles are written back only through the public `ctx.sessionTitle` service, and model calls go only through `ctx.llm` routes; it does not touch the UI and does not read the database.

## Development and testing

```sh
npm test
node --test test/*.test.mjs
```

17 tests: message filtering (only `source.kind === 'user'` with text), 20-character / emoji-safe truncation, control-character cleanup, over-budget selection by "first + recent window"; plus a full-chain smoke — a fake host fires `turn/end` through generate → truncate → rename, checking the v4 `source` shape of request messages, subagent skipping, and that a model error does not write garbage.

## Known limits

- **Only fires at turn end**: it acts after `turn/end`; a session still in progress is not renamed. Pressing stop mid-turn also counts as one end.
- **If the local model is down, it only logs**: on request failure (service off, route missing, timeout) it keeps the old title and never corrupts it.
- **Service hard cap**: over 80 bytes is truncated again by the service.
- **Depends on two seams**: the `ctx.sessionTitle` service and the `ctx.llm` routes; if upstream changes these seams, this plugin must follow.
- **Restart required**: the host half is an in-process module.
